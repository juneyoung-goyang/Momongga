프로그램 3개, 데이터 1개, AI 2개

학생 앱, 직원 POS, 관리자 프로그램이 하나의 데이터로 실시간 연결돼요. AI는 두 곳에서 일해요. 시간대별 대기를 예측해 덜 붐비는 시간으로 예약하도록 돕고, 학생의 말을 SQL로 바꿔 오늘 메뉴에서 알맞은 메뉴를 찾아요.

전체 흐름

위에서 아래로 데이터가 흐르고, 직원 POS의 주문 기록이 다시 모델 학습으로 돌아가요.

AI ① 대기 예측 모델

멘토링에서 정한 대로, 무엇을 보고(X) 무엇을 맞히는지(Y)를 분명히 했어요.

X 인자 (모델이 보는 정보)이유
시각 (분 단위)점심 피크 11:30~13:30
요일요일마다 수업 시간표가 달라요
직전 15분 주문 수지금 몰리는 정도
시험기간 여부수업이 줄어 방문이 흩어져요
교내 행사 여부외부 방문객이 늘어요
비 여부교외 식사가 줄어요
피크타임 여부시각을 구간으로 묶은 값
Y (맞히는 값)모델
15분 뒤 혼잡도 (원활·보통·혼잡)분류 RandomForestClassifier
15분 뒤 예상 대기시간 (분)회귀 RandomForestRegressor
  • 앱이 보여주는 메뉴별 예상 수령 시간 = 모델 예측(공통 혼잡) + 그 식당 주방의 대기열 + 메뉴 조리 시간
  • 단순 규칙("다음 15분도 직전 15분과 같다")과 정확도·오차를 비교해 관리자 화면에 보여줘요

현재는 합성 데이터 500건으로 예측 과정을 검증한 단계예요. 실제 주문 기록이 쌓이면 POS에서 내보내 다시 학습해요.

AI ② 자연어 메뉴 추천 (NL2SQL)

예: "고기 말고 국물 있는 거, 10분 안에"

  1. 학생 앱이 질문, 오늘 메뉴 표 구조, 지금 대기 예측, (로그인했다면) 남은 칼로리와 최근 주문을 묶어요.
  2. Netlify 서버 함수가 학교 BAZE 게이트웨이의 LLM에 보내요. API 키는 서버에만 있어요.
  3. LLM이 SQL, 추천 이유, 추천 메뉴, 다음 행동(예약 제안 등)을 JSON으로 돌려줘요.
  4. 앱이 SQL을 검사해요. SELECT만, menus 표만 허용해요.
  5. 브라우저 안 SQLite(sql.js)에서 실행해 실제로 있는 메뉴만 보여주고, 'AI가 만든 SQL'도 펼쳐 볼 수 있어요.
  6. 10분 안에 받기 어려우면 추천 시각 예약으로 바로 담을 수 있어요.

책임 있게 쓰기 위한 장치

  • API 키는 서버 환경 변수에만, 화면 코드에는 없음
  • LLM이 만든 SQL은 실행 전에 검사
  • 비회원은 개인 기록 없이 추천
  • 사람(IP)당 1분 15회 요청 제한, 다른 사이트 호출 차단
  • LLM 연결이 끊겨도 규칙 기반으로 같은 흐름 유지
