## 1. 문제 정의 (20점)

명지전문대 학생식당은 점심 피크(11:30~13:30)에 주문과 수령 줄이 길어집니다. 학생은 지금 가면 몇 분을 기다릴지 알 수 없어 쉬는 시간 안에 식사를 마치기 어렵고, 조리실은 주문이 한꺼번에 몰려 메뉴별 진행 상황을 파악하기 어렵습니다. 식당을 위탁 운영하는 쪽은 피크 인력 배치, 품절, 재료 발주를 경험에 의존합니다.

저희는 이 문제를 학생·조리 직원·운영 관리자 세 입장으로 나누어 보았습니다. 핵심 목표는 대기 시간을 보여주는 데서 그치지 않고, **AI 예측으로 학생이 덜 붐비는 시간에 예약하도록 행동을 바꿔 피크를 분산하는 것**입니다. 이를 위해 학생 앱, 직원 POS, 관리자 프로그램을 하나의 데이터로 연결한 학생식당 플랫폼 'MJC Table'을 만들고 있습니다.

## 2. AI 도구·활용 방식 (25점)

**① 대기 예측 (scikit-learn 랜덤 포레스트)**
- 입력(X): 시각, 요일, 직전 15분 주문 수, 시험기간, 교내 행사, 비, 피크타임 여부
- 출력(Y): 15분 뒤 혼잡도(원활·보통·혼잡, 분류 모델)와 15분 뒤 예상 대기시간(분, 회귀 모델)
- 모델이 만든 시간대별 예측 파일을 학생 앱·직원 POS·관리자가 직접 읽고, 식당별 주방 대기열과 합쳐 메뉴별 예상 수령 시간과 예약 추천 시각("13:00에 오면 7분")을 보여줍니다.
- "다음 15분도 직전 15분과 같다"는 단순 규칙과 비교해 혼잡도 정확도 95% 대 77%, 대기시간 평균 오차 1.04분 대 1.69분을 확인했습니다. 현재는 합성 데이터 500건으로 예측 과정을 검증한 단계이며, 직원 POS에서 실제 주문 기록을 내보내 다시 학습하는 구조까지 구현했습니다.

**② 자연어 메뉴 추천 (LLM + NL2SQL)**
- 학생이 "고기 말고 국물 있는 거, 10분 안에"처럼 말하면, 학교가 제공하는 BAZE LLM 게이트웨이가 메뉴 표를 조회하는 SQL과 추천 이유를 만들고, 앱이 SQL을 검사한 뒤 브라우저 안 SQLite에서 실행해 실제로 있는 메뉴만 추천합니다. 시간 안에 받기 어려우면 추천 시각 예약을 바로 제안합니다.
- 로그인한 학생은 남은 칼로리와 최근 주문까지 반영해 추천합니다.

**AI 효과 측정과 책임 있는 사용**
- 관리자 대시보드에서 'AI 추천 시각으로 예약한 주문 수', '예약으로 줄인 대기 합계', 'AI 추천 질문 수'를 실시간으로 집계합니다.
- API 키는 서버 환경 변수에만 두고, LLM이 만든 SQL은 실행 전에 검사(SELECT·메뉴 표만 허용)하며, 비회원은 개인 기록 없이 추천하고, 요청 수를 제한합니다. LLM 연결이 끊겨도 규칙 기반으로 같은 흐름이 유지됩니다.

**개발 과정의 AI 활용**
- 학교에서 제공한 Claude Pro로 기획·디자인·코드 초안을 만들고, 팀이 모든 화면을 직접 눌러 검증하며 수정했습니다. AI가 만든 결과에서 글자 대비 부족, API 키 노출 위험, 다른 회사 브랜드 이미지 사용 위험을 찾아 고쳤습니다.
